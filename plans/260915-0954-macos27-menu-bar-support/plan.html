Engineering Roadmap • Release 2.0.0 Architecture

macOS 27 menu bar support — Skein 2.0.0

macOS 27 broke both mechanisms Skein is built on. A status item longer than roughly half the display width is dropped instead of pushing other items off screen, and status items are no longer per-app windows, so enumeration, images, hit testing, temp-show and moving all fail. This plan rebuilds every affected subsystem behind one runtime gate (MenuBarPlatform.usesMenuBarAgent) and ships it as a single 2.0.0 release.

What Apple Documents for macOS 27

Full investigation of Apple Developer DocC documentation, WWDC26 transcripts, and release notes confirms that Apple officially documents nothing regarding MenuBarAgent, WindowServer compositing, or layout tables. Every mechanism in this plan is backed by verifiable hardware probes and runtime checks.

Topic Documented Reality vs. Undocumented Architecture Visible Apple Source URL
Undocumented Architecture Apple documents nothing about MenuBarAgent, single-window compositing, the length cliff, or the layout table. Every macOS 27 mechanism in this plan is reverse-engineered and verified on hardware, so each carries a runtime check. https://developer.apple.com/documentation/macos-release-notes/macos-27-release-notes
Expanded Interface Delegate The only new status item API, NSStatusItem.expandedInterfaceDelegate / NSStatusItemExpandedInterfaceSession (27.0), covers an app's own item. Diagram 1 • Two-Track Pipeline

This visual architecture maps how the eight phases build upon each other (Track 1) and details the runtime execution sequence on macOS 27 (Track 2), tracing from the initial platform gate through collapse math, Accessibility snapshots, event reveals, ScreenCaptureKit strip capture, and atomic layout table writes.

Single WindowServer Window: Window 550 ("Menubar") owned by MenuBarAgent hosts every status item; individual window IDs are nonexistent. • Order-of-Truth: TrailingItemPreferredPositions in ~/Library/Group Containers/com.apple.MenuBar/.../com.apple.MenuBar.plist controls item order. • Permissions Boundary: Read/write of Apple group container requires Full Disk Access. Hide/show operates without FDA via divider length + spacers. • Zero Silent Restarts: Applying layout changes reloads MenuBarAgent exactly once after explicit user confirmation, with automatic rollback if unverified.

Post-Review Validation Log (Session 1 • 2026-09-15)

A critical-questions validation interview resolved 4 genuine technical trade-offs regarding privacy, flash intervals, reload confirmations, and multi-display spacer spans.

Tradeoffs: Always-Hidden Section Images

Question: The plan never reveals that section automatically for capture, because revealing can expose icons the user deliberately hid (e.g. during screen sharing); its slots stay empty until the user shows it once. Keep that?

Options Considered:

  • Leave empty until shown manually (Recommended)
  • Reveal briefly on opening Menu Bar Layout

Confirmed Decision: Leave empty until shown manually

Rationale: Privacy of deliberately hidden items outweighs complete images. Preserves security during screen sharing and presentations.

Risks: Hidden-Section Reveal-Capture

Question: Opening Menu Bar Layout, search or Skein Bar reveals the hidden section for about half a second to capture missing images, once per item set until items or screens change. Acceptable?

Options Considered:

  • Accept (Recommended)
  • Only when opening Menu Bar Layout

Confirmed Decision: Accept

Rationale: Required for real images in search and Skein Bar under the Screen Recording decision. Single flash per configuration change is bounded and acceptable.

Architecture: Closing Menu Bar Layout with Unapplied Changes

Question: Closing Menu Bar Layout with unapplied changes?

Options Considered:

  • Ask Apply / Discard / Keep Editing (Recommended)
  • Discard silently

Confirmed Decision: Ask Apply / Discard / Keep Editing

Rationale: Keeps every MenuBarAgent restart strictly user-confirmed. Eliminates surprise reloads while preventing accidental loss of complex drag configurations.

Assumptions: Spacers per Divider

Question: Up to 6 spacers per divider (12 hidden status items) on the three-display setup, with a one-time Cmd-drag if LEGACY_SEED=no. Acceptable?

Options Considered:

  • Accept (Recommended)
  • Spacers for the hidden divider only

Confirmed Decision: Accept

Rationale: Hiding must work on the 3008pt display for both sections. Multi-display setup requires sufficient aggregate spacer span.

Open Technical Questions

Question: Whether MenuBarAgent can re-sort without a restart (spike S3, LIVE_RESORT).

Resolution Architecture: If yes, Phase 6 skips the restart and waits 1s for automatic reload.

Question: Whether the app can read the table without Full Disk Access (spike S2).

Resolution Architecture: If not, Phase 3 lists items without the table (using Accessibility x-order and matching own items by window frame) as specified.

Question: Whether Full Disk Access lets a Personal Team signed app persist writes to Apple's group container under macOS 27's deny-by-default policy (spike S2, WRITE_WITH_FDA).

Resolution Architecture: If not, moving is not implementable and the plan stops before Phase 6 to escalate to the maintainer.

Emergency Disaster Recovery Protocol

If MenuBarAgent's layout table ever becomes corrupted outside Skein's automated backup restoration flow, run this recovery command in a Terminal granted Full Disk Access to reset the menu bar to native defaults: 

defaults delete "$HOME/Library/Group Containers/com.apple.MenuBar/Library/Preferences/com.apple.MenuBar" TrailingItemPreferredPositions && killall MenuBarAgent
